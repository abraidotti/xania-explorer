    Armour-class and saving-throw bonuses are free under the item-points rule¶

    presentcodewrong behaviour

    AFFECT_DATA::worth prices each affect for the item-points balance rule (immworth). Its case for Ac and the Saving* locations reads if (modifier < 0) if (modifier > 0), which can never be true, so these bonuses cost nothing. Builders' items can carry any amount of AC and saves without the check noticing (see Equipment).

    Fix. Charge one point per −1, as the code intends:

        case AffectLocation::Ac:
        if (modifier < 0)
            return Value{0, 0, -modifier};
        break;

    Then re-run immworth on existing items: Equipment lists the ones that would newly exceed the limit.

    Losing a level doesn't undo what gaining it gave¶

    presentcodewrong behaviour

    From level 26, dying can cost a level (fight.cpp, lose_level). advance_level adds HP and mana from the character's current stats with a squared mana factor; lose_level removes them using maximum stats and an older mana formula. A death followed by re-levelling therefore changes a character's max HP and mana: for mages, mana grows a little with each cycle.

    Fix. Make the two mirror each other. Simplest: have lose_level remove the average of what advance_level would give at the same stats (share one helper for both), or record each level's actual gains in the player file and remove exactly those.

    Booting crashes if a two-way exit's return exit leads nowhere¶

    fixedcodecrash risk

    map_exit_destinations checks that each two-way exit's reverse exit leads back. The test exit_rev && exit_rev->u1.to_room->vnum != room.vnum dereferences to_room without checking it; the logging two lines later does check it, so the case was anticipated. An area whose return exit is cosmetic (−1) or dangling would crash the MUD at boot.

    Fix. Check the destination first:

    if (auto &exit_rev = to_room->exits[reverse(direction)];

    Booting crashes if a shop names a missing shopkeeper¶

    fixedcodecrash risk

    load_shops looks up the shopkeeper's prototype and immediately writes to it. If the vnum doesn't exist, get_mob_index returns null and the MUD crashes during boot instead of reporting the bad shop.

    Fix. Report and skip the shop:

    mobIndex = get_mob_index(shop.keeper, logger);
if (!mobIndex) {
    logger.bug("Load_shops: shopkeeper #{} not found.", shop.keeper);
    continue;
}
mobIndex->shop = std::move(shop);

    The area and map tools write part of their output to the screen¶

    presentcodecosmetic

    The areas and map utilities (src/apps) take an output file, but some of their DOT output is printed with fmt::print("…"), which goes to stdout. Writing to a file produces a broken graph.

    Fix. Pass the file handle to every DOT line, e.g. fmt::print(out_file, "}}\n");, and give render_area the out_file it already receives for its room and exit lines.

    The Mud School reset comment contradicts the code¶

    unknowncodecosmetic Area.cpp isn't in this checkout

    Area.cpp's comment says Mud School resets every 2 minutes when occupied and every minute when empty. The code sets its age to 10 after each reset against a threshold of 15 (it is never flagged empty), so it resets every ~5 area pulses, about 2.5–7.5 minutes.

    Fix. Decide which is intended. To match the comment, set age_ to RoomResetAgeOccupiedArea - 2 (and - 1 when empty); otherwise correct the comment.

    Method¶

    How these numbers are calculated
    • Code checks search the C++ source for a specific faulty pattern, each verified by reading the code. A branch that fixes the code shows the check as fixed. Checks whose faulty code only crashes on bad data are latent until some data triggers them.
    • Data checks use the area parser's load-integrity results, which mirror what the C++ loader rejects (fatal) or logs.
    • Content checks reuse the other systems: items no reset places (objects the C++ creates itself, like corpses and the Mud School kit, are excluded), mobs that never spawn, rooms with no walking route from recall, and area files that aren't loaded.
    • Severity: crash risk, wrong behaviour, cosmetic. Kinds: code, data, content.
    • Statuses counted as open: latent, present.
